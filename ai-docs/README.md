# ai-docs — база знаний, на которой работает агент

Это **единственный источник правды** для AI-агента `backend-developer`. У агента
нет вшитых знаний о наших конвенциях: всё, что он делает, он сначала находит
здесь. Если правило не записано в `ai-docs` — для агента его не существует.

Отсюда следует главное правило сопровождения: **меняется процесс — меняется
документ**, а не промпт агента.

## Структура

| Каталог | Что внутри | Когда агент это читает |
|---|---|---|
| `00-meta/` | как устроена сама база, формат документов | один раз в начале задачи |
| `10-process/` | жизненный цикл тикета, ветки, коммиты, MR, DoD | всегда |
| `20-architecture/` | целевая архитектура, слои, интеграции, ADR | при проектировании |
| `30-conventions/` | правила кода: Java, Spring, REST, БД, логи, тесты, безопасность | перед написанием кода |
| `40-projects/` | карточки конкретных сервисов | когда известен сервис из тикета |
| `50-runbooks/` | пошаговые операционные инструкции | при сборке, запуске, разборе ошибок |
| `60-glossary/` | доменные термины и сокращения | при разборе формулировок тикета |

Навигационная карта — [`INDEX.md`](INDEX.md). Формат документа —
[`00-meta/doc-format.md`](00-meta/doc-format.md).

## Как агент сюда ходит

Через два инструмента ts-сервера:

- `docs_read` без аргументов → карта базы + каталог всех документов;
- `docs_search` → поиск по тексту, заголовкам, тегам и frontmatter;
- `docs_read` с путём или `id` → полный текст документа (или одна секция).

## Как добавить правило

1. Выбрать каталог по таблице выше.
2. Скопировать frontmatter из `00-meta/doc-format.md`.
3. Писать императивом: «делай так», «так нельзя», а не «желательно».
4. Приводить пример кода — агент копирует образцы точнее, чем следует описаниям.
5. Добавить документ в `INDEX.md`.

Правило без примера и без явного запрета соблюдается хуже всего.
