# Как агент читает эту базу

## Принцип

Агент не знает конвенций компании. Он знает только одно: **прежде чем принять
любое решение о коде, найти соответствующее правило в `ai-docs`**.

## Обязательный минимум на старте задачи

1. `docs_read` без аргументов — получить карту и каталог.
2. `docs_read("10-process/ticket-lifecycle.md")` — процесс.
3. `jira_get_issue(<TICKET>)` — содержание задачи.
4. `docs_search` по ключевым словам из тикета — найти релевантные конвенции.

## Приоритет источников

При конфликте выигрывает более узкий документ:

```
карточка проекта (40-projects/)
  > ADR (20-architecture/adr/)
    > конвенция (30-conventions/)
      > общая архитектура (20-architecture/)
        > существующий код в репозитории
```

Код репозитория — **последний** аргумент. Если код противоречит конвенции,
это долг, а не правило: следовать конвенции и упомянуть расхождение в MR.

## Если правила нет

Не выдумывать. Порядок действий:

1. Повторить `docs_search` с другими формулировками (рус. и англ. термины).
2. Посмотреть, как сделано в соседнем коде того же модуля, и назвать это
   «решение по аналогии».
3. Явно написать в описании MR раздел `Решения вне ai-docs` с перечнем того,
   что пришлось додумать, и предложением дополнить базу.

Молча принятое недокументированное решение — ошибка процесса.

## Чего в базе нет и не будет

- Секретов, токенов, паролей, внутренних URL с креденшелами.
- Персональных данных.
- Копий кода целых сервисов — только эталонные фрагменты.
