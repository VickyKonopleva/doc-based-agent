# Оформление merge request

MR создаётся агентом **в статусе draft**. Снимает draft и назначает ревьюеров
человек.

## Заголовок

```
<TICKET>: <что сделано, в повелительном наклонении, по-русски или по-английски>
```

```
BACK-1234: добавить ретраи для коллбэков платёжного шлюза
```

## Описание — обязательный шаблон

```markdown
## Что сделано
Короткий список изменений по существу.

## Зачем
Проблема из тикета своими словами. Ссылка на тикет.

## Как проверить
Команды и шаги, по которым ревьюер воспроизведёт результат.

## Применённые конвенции
- conv-rest-api — пагинация ответа
- conv-persistence — миграция Liquibase

## Решения вне ai-docs
То, что пришлось додумать, потому что правила нет в базе.
Если таких решений нет — написать «нет».

## Риски и обратная совместимость
Миграции, изменения контракта, фичефлаги, план отката.

## Чеклист
- [ ] `./mvnw clean verify` локально зелёный
- [ ] добавлены/обновлены тесты
- [ ] логи и метрики по conv-observability
- [ ] нет секретов в диффе
- [ ] обновлена документация сервиса (если контракт менялся)
```

## Размер

Цель — до ~400 изменённых строк. Больше — разбить на несколько MR
и сказать об этом в описании.

## Нельзя

- Пустое описание или «см. тикет».
- MR без тестов при изменении логики.
- Смешивать рефакторинг и фичу в одном MR.
