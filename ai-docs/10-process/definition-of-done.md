# Definition of Done

Задача считается сделанной, когда выполнено **всё** перечисленное.

## Функционально

- Реализованы все acceptance criteria тикета. Если их не было — реализовано
  явно сформулированное и записанное в MR понимание задачи.
- Обработаны граничные случаи: пустой ввод, null, превышение лимитов,
  недоступность внешней системы, повторный вызов (идемпотентность).

## Код

- Соответствует `30-conventions/*`; расхождения объяснены в MR.
- Нет закомментированного кода, `TODO` без номера тикета, `System.out.println`.
- Публичные методы и неочевидные решения прокомментированы по существу.

## Тесты

- Unit-тесты на новую бизнес-логику.
- Интеграционный тест на новый или изменённый эндпоинт/консьюмер.
- `./mvnw clean verify` проходит локально.
- Покрытие нового кода не ниже порога из `30-conventions/testing.md`.

## Наблюдаемость

- Значимые события логируются на нужном уровне, без чувствительных данных.
- Для новой внешней интеграции добавлены метрики и таймауты.

## Совместимость

- Изменение API обратно совместимо либо сопровождается версионированием.
- Миграция БД обратима или имеет описанный план отката.

## Оформление

- Ветка и коммиты по `proc-branching-commits`.
- Draft MR по `proc-merge-request`.
