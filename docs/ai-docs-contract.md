# Контракт между агентом и базой знаний

Агент не хранит знаний о конвенциях — он читает вашу базу `ai-docs` через два
инструмента `be-tools`:

| Инструмент | Что делает |
|---|---|
| `docs_read` без аргументов | карта базы: содержимое `INDEX.md` (если есть) + каталог всех документов |
| `docs_read({ path })` | документ целиком — по пути, по `id` из frontmatter или по хвосту пути |
| `docs_read({ path, section })` | одна секция по совпадению в заголовке |
| `docs_search({ query, type?, tag?, limit? })` | ранжированный поиск с цитатами строк |

База подключается снаружи — путём в файловой системе или клоном из GitLab,
см. [`connecting-ai-docs.md`](connecting-ai-docs.md). В репозитории агента её нет.

## Что сервер читает

Рекурсивно все `*.md` и `*.mdx` из `AI_DOCS_PATH`. Каталоги, начинающиеся с
точки, и `node_modules` пропускаются.

**База работает без какой-либо подготовки.** Frontmatter, `INDEX.md` и
структура каталогов — не обязательны: без них поиск идёт по тексту, заголовкам
и путям файлов. Всё перечисленное ниже просто повышает точность.

## Frontmatter (необязательный, но полезный)

```yaml
---
id: conv-rest-api            # стабильный идентификатор; по нему можно открыть документ
title: Конвенции REST API    # сильнее всего влияет на ранжирование
type: convention             # фильтр docs_search({ type })
tags: [rest, http, pagination]
status: active               # deprecated → агент обязан предупредить
owner: platform-team
updated: 2026-09-15
---
```

Веса при ранжировании `docs_search`:

| Совпадение | Вес |
|---|---|
| `title` | 12 |
| `id` | 10 |
| `tags` | 8 |
| `scope` | 5 |
| путь файла | 4 |
| строка-заголовок в тексте | 4 |
| обычная строка текста | 1 |

Отсюда практический вывод: **название документа важнее его объёма**. Документ
с точным заголовком находится, документ «Разное» — нет.

Если YAML во frontmatter не парсится, документ не теряется: он остаётся
доступен по тексту, а `docs_read()` выводит предупреждение с именем файла и
ошибкой.

## Что помогает агенту больше всего

1. **`INDEX.md` в корне базы.** Отдаётся целиком при каждом старте задачи. Это
   единственное место, где можно задать порядок чтения: «сначала процесс,
   потом карточка сервиса, потом конвенции».
2. **Самодостаточные заголовки `##`.** Агент умеет запросить одну секцию;
   заголовок «Пагинация» работает, «Детали» — нет.
3. **Карточки сервисов.** Без них агент не определит, в каком репозитории
   делать изменение. Это самый частый повод остановиться и переспросить.
4. **Императив и примеры кода.** «DTO объявляй как `record`» + фрагмент кода
   работает заметно лучше, чем «обычно мы используем record».
5. **Явные блоки запретов.** Запрет, выделенный списком, соблюдается; запрет
   в середине абзаца — теряется.

## Как сказать агенту, где что лежит

Имена и структура вашей базы агенту заранее неизвестны. Он находит документы
через `docs_read()` и `docs_search`, но путь короче, если заполнить
[`.gigacode/ai-docs-pointers.md`](../.gigacode/ai-docs-pointers.md) — список
«тема → путь или id» для нескольких ключевых документов (процесс, ветки и
коммиты, шаблон MR, DoD, карточки сервисов).

Это единственное место, где конфигурация агента зависит от устройства вашей
базы. Пусто — агент работает, просто тратит больше шагов на поиск.

## Ограничения

- Файлы читаются с диска при каждом вызове, кеш не инвалидируется по времени:
  правки в базе видны сразу, перезапуск сервера не нужен.
- Бинарные вложения (`.png`, `.pdf`, `.xlsx`) не читаются. Если требование
  живёт только в картинке, агент его не увидит.
- Агенту запрещено писать в базу. Предложения по её дополнению он выносит
  отдельным разделом в описание MR.
