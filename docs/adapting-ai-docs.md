# Как наполнить ai-docs под свой контур

Поставляемая база — рабочий каркас с реалистичным, но **примерным**
содержимым (Java 21 / Spring Boot 3 / PostgreSQL / Kafka / GitLab). Качество
агента определяется качеством этой базы, поэтому порядок замены имеет значение.

## Порядок внедрения

**Шаг 1 — то, без чего агент бесполезен.**

- `10-process/branching-and-commits.md` — ваши имена веток и формат коммитов.
- `10-process/merge-request.md` — ваш шаблон описания MR.
- `40-projects/` — карточки **реальных** сервисов по `_template.md`.
  Без них агент не поймёт, где делать изменение.
- `50-runbooks/local-build-and-run.md` — ваши команды сборки.

**Шаг 2 — то, что определяет качество кода.**

- `30-conventions/*` — вычитать каждый документ и привести к вашим правилам.
  Расхождение здесь даёт MR, который завернёт ревьюер.
- `60-glossary/glossary.md` — ваши доменные термины.

**Шаг 3 — то, что накапливается со временем.**

- `20-architecture/adr/` — переносите решения по мере их принятия.
- `50-runbooks/common-failures.md` — пополняйте из реальных падений.

## Как писать, чтобы агент соблюдал

| Работает | Не работает |
|---|---|
| «DTO объявляй как `record`» + пример | «обычно мы используем record» |
| таблица «ситуация → HTTP-код» | «возвращайте подходящий код» |
| блок `## Нельзя` со списком | запрет в середине абзаца |
| пример кода | описание кода словами |
| один документ — одна тема | «общие правила разработки» на 40 экранов |

Агент воспроизводит примеры точнее, чем следует прозе. Каждое нетривиальное
правило — с фрагментом кода.

## Как проверить, что базы хватает

```bash
./scripts/run-agent.sh BACK-1234 --plan
```

В плане агент перечисляет применённые конвенции с их `id`. Если в разделе
«Решения вне ai-docs» что-то есть — это точный список недостающих документов.

Отдельная команда для аудита темы:

```
/docs-gap идемпотентность консьюмеров
```

## Сопровождение

- `ai-docs` живёт в git и ревьюится как код.
- Устаревший документ помечается `status: deprecated`, а не удаляется:
  агент обязан его игнорировать и сказать, что нашёл устаревшее правило.
- Новый документ обязательно добавляется в `INDEX.md` — это карта, с которой
  агент начинает.
- Поле `updated` в frontmatter обновляется при каждой правке по существу.

## Вынести в отдельный репозиторий

В реальном контуре `ai-docs` обычно общий для нескольких агентов и команд.
Тогда:

```bash
git submodule add git@git.company.ru:ai/ai-docs.git ai-docs
```

либо оставить его где угодно и указать путь:

```bash
AI_DOCS_PATH=/Users/me/work/ai-docs
```

Сервер инструментов работает с любым расположением — он читает `AI_DOCS_PATH`.
