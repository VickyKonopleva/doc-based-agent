# Подключение базы знаний

База знаний `ai-docs` **не входит в этот репозиторий**. Она ваша, живёт
отдельно и сопровождается командой. Агент получает к ней доступ одним из двух
способов.

## Вариант 1. Локальный путь

Если чекаут базы уже есть на машине — просто укажите путь:

```bash
# .env
AI_DOCS_PATH=/Users/me/work/ai-docs
```

Путь может быть абсолютным или относительным от корня этого проекта.
Правки в базе видны агенту сразу: файлы читаются при каждом вызове, перезапуск
сервера инструментов не нужен.

## Вариант 2. Репозиторий GitLab

```bash
# .env
AI_DOCS_GIT_URL=git@git.company.ru:ai/ai-docs.git
AI_DOCS_REF=master
AI_DOCS_PATH=ai-docs          # куда клонировать; этот путь в .gitignore
```

```bash
./scripts/sync-ai-docs.sh
```

Скрипт клонирует репозиторий или подтягивает свежую ветку в уже существующий
клон. Запускайте его перед работой, чтобы агент видел актуальные правила.

Альтернатива для тех, кто предпочитает submodule:

```bash
git submodule add git@git.company.ru:ai/ai-docs.git ai-docs
```

Тогда `AI_DOCS_PATH=ai-docs`, а `sync-ai-docs.sh` не нужен.

## Что агент ожидает от базы

Ничего обязательного: работает любая папка с markdown. Детали — какие поля
frontmatter повышают точность поиска, как ранжируются совпадения, что даёт
`INDEX.md` — в [`ai-docs-contract.md`](ai-docs-contract.md).

Короткая версия, по убыванию пользы:

1. `INDEX.md` в корне — агент читает его целиком в начале каждой задачи.
2. Карточки сервисов — без них агент не определит, где делать изменение.
3. `title` во frontmatter — сильнее всего влияет на поиск.
4. Самодостаточные заголовки `##` — агент умеет читать одну секцию.

## Подсказки по навигации

Структура вашей базы агенту заранее неизвестна, и он не должен ссылаться на
документы, которых не видел. Чтобы он не тратил шаги на поиск одного и того
же, заполните [`.gigacode/ai-docs-pointers.md`](../.gigacode/ai-docs-pointers.md) —
список «тема → путь или `id`» для десятка ключевых документов.

Файл необязателен. Пусто — агент найдёт сам, просто за большее число вызовов.

## Чего в базе может не хватать

Процесс «тикет + PR аналитики» новый, и в базе, сложившейся раньше, его
описания может не быть. Готовые черновики лежат в
[`proposed-ai-docs/`](proposed-ai-docs/) — скопируйте в свой репозиторий то,
что подойдёт:

- `spec-driven-flow.md` — как читать PR аналитики, трассируемость требований,
  стоп-ситуации;
- `merge-request-additions.md` — ссылка на спеку и таблица требований в
  описании MR.

Проверить, чего не хватает по конкретной теме:

```
/docs-gap идемпотентность консьюмеров
```

Или прогнать реальную задачу в режиме плана — агент перечислит всё, что ему
пришлось додумать:

```bash
./scripts/run-agent.sh BACK-1234 456 --plan
```

Это самый точный способ понять, где в базе дырки: список берётся из реальной
работы, а не из предположений.

## Если база недоступна

Агент не станет работать по памяти: инструменты `docs_read` и `docs_search`
вернут ошибку с указанием настроенного пути и подсказкой, как это починить,
а роль прямо запрещает продолжать без базы знаний.
