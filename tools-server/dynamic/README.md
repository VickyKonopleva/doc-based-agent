# dynamic/ — инструменты, которые агент пишет себе сам

Пусто по умолчанию, как и `.gigacode/skills/`. Сюда попадает только то, что
агент создал через `tool_create`, столкнувшись с повторяющейся операцией.

- Один инструмент — один файл `<имя_инструмента>.tool.ts`.
- `export default defineTool({ ... })`.
- Хелперы импортируются из `./_sdk.js`, см. [`_sdk.ts`](_sdk.ts).
- Загрузчик берёт только `*.tool.ts`; `_sdk.ts` и прочее игнорируются.

Файлы версионируются: инструмент, придуманный в ходе задачи, проходит ревью в
том же pull request, что и изменения сервиса. Прижившиеся стоит перенести в
`src/tools/` как встроенные.

## Проверка перед тем, как заводить инструмент

Инструмент оправдан, только если возможности **нет другого способа получить**:

| Сначала спроси | Если да — инструмент не нужен |
|---|---|
| это уже умеет подключённый MCP-сервер? | пользуйся им |
| это делается парой команд в оболочке? | делай командами |
| это разовое действие в рамках одной задачи? | делай руками |
| это правило компании, а не операция? | предложи документ в базу знаний |

Инструменты здесь — интерфейсы к возможностям, а не обёртки над командами.
Поэтому, например, создание pull request инструментом не оформляется: адрес
репозитория известен, ветка запушена, а API Bitbucket доступен и напрямую, и
через MCP-сервер.
