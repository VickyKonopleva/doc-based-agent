# hooks/

Пусто по умолчанию. Сюда кладутся скрипты, которые GigaCode CLI вызывает
вокруг действий агента; подключаются в `settings.json`.

Практически полезные кандидаты:

- `pre-commit-secret-scan.sh` — отказать в коммите, если в диффе похоже на
  секрет;
- `post-edit-spotless.sh` — `./mvnw spotless:apply` после правки `*.java`;
- `pre-push-verify.sh` — не дать запушить ветку с красной сборкой;
- `pre-push-no-force.sh` — запретить `--force` и пуш в защищённые ветки.

Хук — жёсткая гарантия, инструкция в промпте — мягкая. Всё, что должно
выполняться **всегда**, выносите в хук, а не в текст роли.

Это особенно важно здесь: в схеме GigaCode нет блока `permissions` с
шаблонами команд. Доступ ограничивается на трёх других уровнях —
`mcp.allowed` для серверов, `includeTools`/`excludeTools` для инструментов
сервера, `tools`/`disallowedTools` для агента, — но ни один из них не умеет
сказать «`git push`, но не `--force`». Такое закрывается только хуком.
