# skills/ — пусто по умолчанию

Предустановленных скилов у агента нет. Это не упущение: процедуры работы
живут в базе знаний `ai-docs`, которую сопровождает команда и которую можно
менять, не трогая конфигурацию агента.

Скил, повторяющий документ из базы знаний, — вред: две копии одного правила
неизбежно разойдутся, и агент начнёт выполнять устаревшую.

## Кто сюда пишет

Сам агент, через инструмент `skill_create`, когда поймал повторяющуюся
последовательность шагов, которой в базе знаний нет как документа. Инструмент
проверяет frontmatter перед записью: битый YAML, несовпадение имени,
превышение лимитов — и файл не создаётся.

Созданный скил попадает в pull request и проходит ревью наравне с кодом.

## Граница

| Что заметил агент | Чем это закрывается |
|---|---|
| механическая операция с чётким входом и выходом | инструмент в `tools-server/dynamic/` |
| последовательность шагов, требующая суждения | скил здесь |
| правило компании, которого нет в базе | предложение документа в описании PR |

Скил отвечает на вопрос **как выполнить**, база знаний — **что принято**.
Скил ссылается на документ базы, но не пересказывает его.

## Что умеет скил и не умеет база знаний

`paths:` во frontmatter: скил включается сам, когда tool call коснулся
подходящего файла, и остаётся активным до конца сессии.

```yaml
paths:
  - '**/db/changelog/**'
```

База знаний так не умеет — она ждёт, пока агент догадается туда посмотреть.
Это главная причина, по которой скилы вообще нужны.

Активация срабатывает **после** первого обращения к файлу, поэтому такой скил
работает как страховка от «забыл свериться», а не как предварительная
блокировка.

## Руками

```bash
mkdir -p .gigacode/skills/my-skill   # внутри SKILL.md, рядом templates/ и scripts/
cd tools-server && npm run check     # проверит frontmatter и лимиты
```
