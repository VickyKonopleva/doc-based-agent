# skills/ — процедуры агента

Граница, по которой здесь всё разложено:

| Где | Что там живёт | Кто сопровождает |
|---|---|---|
| база знаний `ai-docs` | **что** принято в компании: правила, стандарты, требования | команда, вне этого репозитория |
| `skills/` | **как** агент выполняет повторяющуюся процедуру: шаги, шаблоны, скрипты | владелец агента |
| `tools-server/` | детерминированные операции: вызвать API, прочитать файл, открыть MR | владелец агента |
| `agents/` | кто какую роль играет и что получает в контекст | владелец агента |

Скил **не содержит правил компании** — он напоминает, где их взять, и задаёт
порядок шагов. Так правило остаётся в одном месте и не расходится между базой
знаний и конфигурацией агента.

## Что здесь есть

| Скил | Когда срабатывает |
|---|---|
| `spec-intake` | работа начинается с PR аналитики — разбор спеки в таблицу требований |
| `merge-request` | изменения готовы, пора оформлять draft MR |
| `migration-safety` | tool call затронул файл миграции (`paths:`-гейт) |

## Как добавить свой

```bash
mkdir -p .gigacode/skills/my-skill
```

`SKILL.md` с frontmatter `name`, `description` и, при необходимости,
`priority`, `paths:`, `user-invocable`, `disable-model-invocation`. Рядом
можно держать `templates/`, `scripts/` и справочные `.md`.

Хороший кандидат в скил — процедура, которая:

- выполняется не в каждой задаче (иначе дешевле держать её в роли агента);
- имеет чёткий порядок шагов;
- тянет за собой шаблон или скрипт;
- либо привязана к типу файлов, и тогда её закрывает `paths:`.

`paths:` активирует скил **после** первого обращения к подходящему файлу и
держит активным до конца сессии. Это страховка от «забыл свериться», а не
предварительная блокировка.
